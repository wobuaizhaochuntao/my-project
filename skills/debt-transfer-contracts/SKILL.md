# 法久债转协议制作

用户给出本批 `债转文件*.xlsx`（及可选核对表）后，按本 skill 生成全套 Word 合同并复核。

## 用户需提供

必填：
1. **债转文件 Excel**（每个工作表 = 一条转让链路）
2. **上一批合同模板目录**（含一转、二转/三转/补充协议 `.docx`）
3. **批次号**、**一转日期**、**二转系列日期**（如第12批 / 2026-09-10 / 2026-09-11）
4. **本批 SPV / 中间方资料**：全称、简称、信用代码、地址、开户行、账号；若有法人信息一并写入供应商表

可选：
- `未推送订单.xlsx`（核对债转逻辑与借款人字段）
- 一转对价（默认沿用模板 **30000元**）
- 二转受让方联系地址（若用户指定统一地址，优先用用户指定）

缺资料时先问齐再生成，不要猜测工商字段。

## 脚本（优先执行）

目录：`${KIMI_SKILL_DIR}/scripts/`（依赖：`openpyxl`、`python-docx`）

| 脚本 | 用途 |
|------|------|
| `read_debt_excel.py` | 读取债转文件，输出各表笔数/金额 |
| `generate_contracts.py` | 按 JSON 配置生成 Word |
| `validate_contracts.py` | 核对合同附件、编号、日期；可选核对未推送订单 |
| `update_supplier_workbook.py` | 写入供应商客户录入明细 |
| `example_config.json` | 配置模板（复制后改路径与主体） |
| `common.py` | 公共读写/填表/金额工具 |

典型用法：

```bash
python "${KIMI_SKILL_DIR}/scripts/read_debt_excel.py" "D:/.../债转文件0910.xlsx" --json

# 复制 example_config.json 为本批 config.json（放在当前批次工作目录）后：
python "${KIMI_SKILL_DIR}/scripts/generate_contracts.py" --config config.json --dry-run
python "${KIMI_SKILL_DIR}/scripts/generate_contracts.py" --config config.json
python "${KIMI_SKILL_DIR}/scripts/validate_contracts.py" --config config.json --unpushed "D:/.../未推送订单.xlsx"
```

Agent 应：先写/改本批 `config.json`，再跑生成与核对；不要每次从零手写整套脚本。

## 总流程

```
Task Progress:
- [ ] 1. 读取债转文件，确认工作表与明细
- [ ] 2. 解析链路（直转 / 两段转让）
- [ ] 3. 建立输出目录，选定模板映射
- [ ] 4. 生成一转协议（如有中间方）
- [ ] 5. 生成二转 / 三转 / 补充协议
- [ ] 6. 更新供应商客户录入明细（如需要）
- [ ] 7. 全量核对后交付
```

## 1. 读取债转文件

每个工作表名格式：`转让方简称_受让方简称`（例：`三农信_竣洪`、`焕然_万妙`）。

表头固定 8 列：

| 序号 | 订单号 | 姓名 | 身份证号码 | 电话号码 | 未还本金 | 未还利息(含罚息) | 应还代偿总额 |

技术注意：
- 用 `openpyxl`，对每个 sheet 先 `ws.reset_dimensions()`（部分表 `dimension` 为 A1，否则读不全）
- 金额用 `Decimal`，比较时统一保留两位小数
- 序号须从 1 连续；两段转让订单在两张表中**订单集合与序号应对齐**

## 2. 债转逻辑

来源若有 `未推送订单`，按订单推导期望落表：

1. 取 `担保方名称`、`反担保主体`（去掉末尾 4 位账号后缀）、`受让方名称`
2. **直转**：担保方 == 反担保主体 → 仅 1 张表 `担保方简称_SPV简称`
3. **两段转让**：担保方 ≠ 反担保主体 → 两张表  
   `担保方_反担保方`（一转） + `反担保方_SPV`（后续）
4. 期望表集合必须与债转文件实际 sheet 完全一致

金额口径（未推送 → 债转明细）：

- 未还本金 = 代偿本金 + 回购本金
- 未还利息(含罚息) = 代偿利息(含罚息) + 回购利息 + 回购罚息 + 回购其他
- 应还代偿总额 = 未还本金 + 未还利息
- 姓名全等；身份证/手机号按脱敏后可见位核对

无未推送订单时：仍按 sheet 名生成合同，并在交付时注明“未做来源表逻辑核对”。

## 3. 输出目录与命名

在批次根目录下创建：

```
法久第{N}批一转协议{MMDD}/
法久第{N}批二转协议{MMDD}/
  └── {转让方简称}_{受让方简称}/
```

文件名：

- 一转：`【上海法久&{受让方简称}】一转协议-{YYYYMMDD}.docx`
- 二转系列：`【法久&{转让方简称}&第{N}批】{二转|三转|补充}协议-{YYYYMMDD}.docx`

合同编号（正文）：

| 类型 | 格式 |
|------|------|
| 二转 | `{转出码}-{转入码}-{YYYYMMDD}` |
| 补充 | 同上 + `-1` |
| 三转 | 同上 + `-2` |

转出/转入码见 [parties.md](parties.md)。

## 4. 生成一转协议

适用 sheet：中间方作为受让方（如 `三农信_焕然`、`三农信_锋泰`）。

- 模板：上一批一转协议
- 替换：乙方主体/地址/开户行/账号、签订日期、债权笔数、债权总额中文+数字、批次相关日期串
- 附件表 **6 列**：序号、订单号、姓名、身份证、电话、应还代偿总额（不含本金/利息拆分）
- 对价条款默认保持 **30000元**，除非用户另指定
- 填表：克隆模板样式行，按债转 sheet 顺序写入；金额显示建议统一两位小数

## 5. 生成二转 / 三转 / 补充协议

每个**最终落到 SPV 的链路**一组，共 3 份：

| 类型 | 甲方 | 乙方 | 附件 | 签订日期 |
|------|------|------|------|----------|
| 二转 | 转让方 | 受让方(SPV) | 8 列全量 | 填二转日期 |
| 三转 | 受让方(SPV) | 原转让方 | 8 列全量（与二转同一批订单） | **留空**（`签订日期：`） |
| 补充 | 同二转主体关系 | — | 无附件表 | 填二转日期 |

模板映射：优先用上一批**同转让方**、结构最接近的一组（同担保方优先）；新中间方（如焕然）可借用同类中间方模板（如锋泰），再全文替换主体与账户。

必须替换：
- 第{N}批、日期（`YYYYMMDD` / `YYYY年MM月DD日` / `【YYYY】年【MM】月【DD】日`）
- 旧 SPV 全称 / 地址 / 开户行 / 账号 / 代码 → 新 SPV
- 笔数：`共计【n】笔` / `共【n】笔`
- 协议编号中的主体代码与日期
- 原协议编号（如补充协议引用的二转编号）

生成后清理上一批残留字符串（旧批次号、旧日期、旧 SPV 名与账号）。

## 6. 供应商客户录入明细

若目录中有 `法久--第三方供应商、客户录入明细-*.xlsx`：

- 可合并本批新 SPV 到同一工作簿（基本信息 / 账户信息 / 开票信息 各一行）
- 有截图/资料的字段写入；**成立时间、注册资本、经营范围等未知字段留空**
- 联系人/电话/部门/合作状态/税率等公共运营字段可沿用原表模板行
- 法人姓名以用户提供的法人信息为准

## 7. 核对清单（全部通过再交付）

- [ ] 债转 unique 订单数 = 未推送订单数（若有）
- [ ] 直转/两段转让落表与推导一致；两段订单恰出现 2 次且数值一致（允许 `.5` vs `.50`）
- [ ] 每张附件行数、序号、订单集合、金额与对应 sheet 一致
- [ ] 一转 6 列；二转/三转 8 列；补充无明细表
- [ ] 主体、编号、日期、笔数正确；三转签章日期留空
- [ ] 无上一批批次号/日期/旧 SPV 残留
- [ ] 输出份数 = 一转份数 + 链路组数×3

## 实现约束

- Windows 路径含中文：Python 脚本用 UTF-8 文件落地再执行，避免控制台乱码截断路径
- Word：`python-docx`；批量改 PDF 时用 Word COM 且**逐文件开关 Word**（整批易崩溃）
- 详细主体码表与字段对照见 [parties.md](parties.md)
- 批次示例见 [examples.md](examples.md)

## 交互原则

1. 先确认批次、日期、模板路径、SPV 资料是否齐全
2. 生成前简要列出将产出的合同清单（链路 × 类型）
3. 核对报错只列实质差异；纯小数位显示差异可注明但不当作金额错误
4. 不要编辑用户的 plan 文件；不要擅自 git commit
